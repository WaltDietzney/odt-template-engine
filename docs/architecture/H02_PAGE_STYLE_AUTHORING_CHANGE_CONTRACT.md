## 1. Goal and scope

Native page layout creation and mutation, header/footer geometry and content, page columns, reusable solid/gradient/bitmap fills, bounded inspection, and a programmatically constructed multi-page CV reference. Writer owns pagination. Reuse existing master assignment/succession, Section and Frame capabilities. No general template builder, new layout engine, shape geometry, arbitrary XML API or migration of existing element lifecycle. H03 owns new shapes.

## 2. Public API (proposed)

Retain all existing signatures and return types. Extend definePageLayout(name, options) and setPageLayout(options, master='Standard') with the options below. Add updatePageLayout(name, options): static for explicit layout-identity mutation. Add updatePageStyle(name, options): static for header/footer content only. Add inspectPageLayout(name): array and inspectPageStyle(name): array, read-only, document-local, no DOM exposure. Names are native identifiers, not display names. Unknown target fails; no implicit creation. Existing definePageStyle, assignPageStyle, setNextPageStyle unchanged except fill synchronization on new master creation.

Propose DocumentStyles::defineGradient(string name, array options): void and defineFillImage(string name, string imagePath): void. DocumentStyles remains stateless, current context provider retained; optional package provider added compatibly for image registration, resolved at call time. Existing one-argument construction remains valid; image registration without package provider fails clearly. No global registry. Reuse OdtPackage atomic copy and FillImageRequirement infrastructure. New resource definition methods are additive and not tied to PageLayoutOdtTemplate. Existing DrawTextBox gains setBackground(array options): self or equivalent compatible fluent return type verified against existing class; same semantic fill options as page. Reference validation/materialization occurs before insertion. Existing circular image API and compatibility behavior unchanged. No new shape API.

## 3. Layout options

Existing flat page-width, page-height, orientation, margin-top/right/bottom/left retain existing accepted inputs. New keys: background, background-color, border and border-{top,right,bottom,left}, padding and padding-{top,right,bottom,left}, shadow, border-line-width and border-line-width-{top,right,bottom,left}, columns, header, footer. Header/footer nested keys: height OR min-height, spacing, margin-left/right, dynamic-spacing, same background/border/padding/shadow/double-line options. height maps svg:height; min-height maps fo:min-height; switching removes obsolete alternative; both supplied reject. spacing maps header fo:margin-bottom or footer fo:margin-top. Geometry alone never creates/enables/removes master content. New lengths nonnegative absolute ODF lengths (cm/mm/in/pt/pc), height positive for fixed height; zero allowed for min-height and spacing. Boolean strictly boolean. Colors #RRGGBB, transparent only where applicable. Border syntax none or width/style/color; styles solid/dashed/dotted/double; double-line widths three strictly positive lengths (ODF 1.2 Part 1, 20.241–20.245 and 18.3.26; owner-approved correction 2026-11-18), only with effective double border. Shadow none or color and signed x/y lengths. Shorthand and side-specific keys in same group reject ambiguity; side patch against existing shorthand expands effective values first, shorthand replaces side overrides. Removing/replacing double border removes incompatible width attributes. Preserve unrelated attributes and children. No generic raw XML passthrough.

Omitted options preserve existing properties; explicit background type none clears fill, border none and shadow none clear respective visual effect, padding zero resets padding. No generic null reset. New nested groups reject unknown keys; legacy top-level unknown keys continue to be ignored. Existing seven-key-only legacy setPageLayout path retains characterized behavior including historical validation order; new extended calls and new updatePageLayout are atomic. Characterize legacy before implementation, do not silently fix it. New definitions atomic. No change to legacy permissive length parsing.

## 4. Identity and mutation

setPageLayout continues to target the layout referenced by the master, including shared-layout effects; never silently clone page layouts. updatePageLayout explicitly targets native layout identity. Document this behavior. Page fill belongs to layout and must synchronize drawing-page fill for every master referencing it; on definePageStyle synchronize from referenced layout if supported fill exists. Shared drawing-page style referenced by unrelated layouts must not be mutated: create deterministic collision-safe private drawing-page style for affected master(s), preserving unrelated drawing-page properties. No gratuitous cloning on unchanged fill. Existing master header/footer content untouched by geometry changes. updatePageStyle options header/footer: omitted preserves; OdtElement replaces or creates normal region; null removes normal region; reject mutation if corresponding left/first variant exists rather than silently dropping variant. Empty content via empty native paragraph. Reuse existing resource/style preparation, native block validation and rollback; no unrelated master mutation. No new variant authoring.

Inspection returns native layout/master names, referenced layout/drawing style, next master, header/footer presence, supported properties and resolved fill reference; report unsupported authored fills/properties as unsupported rather than invent defaults. Return detached arrays; no full arbitrary style roundtrip promise. Specify exact shape in tests/docs before implementation.

## 5. Fill semantics

background group: type none (no extra keys), solid (color), gradient (name), bitmap (name, repeat optional default stretch; repeat or stretch only). background-color is shorthand for solid or transparent/none; simultaneous background and background-color rejected. Reference must resolve existing named definition of correct kind in styles.xml; missing/ambiguous resource fails before mutation. Names exact native identifiers; no automatic display-name lookup. Preserve authored resources, never overwrite implicitly. New definitions identical name+semantic definition idempotent, different definition conflict; authored identical only if verified, otherwise reject and allow reference. No global content-addressed deduplication: same package basename+same bytes reused, conflicting bytes rejected by existing atomic package API; multiple references to one named image use one package file. Different names may refer to same package asset. No implicit garbage collection.

Gradient options: type linear, axial, radial, elliptical, square, rectangular; start-color/end-color required; angle numeric degrees (0 <= angle < 360, finite), default 0; border 0..100 integer percent default 0; start-intensity/end-intensity 0..100 default 100; center-x/center-y 0..100 default 50, only where applicable. Two-stop only; preserve existing authored multistop extensions on reference, no multistop authoring. Native draw:gradient in office:styles; angle serialization and type-specific attributes verified against ODF and Writer before coding. No claim that all types render identically without tests. Gradient registry/materializer only as needed, model on existing typed FillImage infrastructure; no generic registry rewrite.

Bitmap: local readable PNG/JPEG, verify actual format and extension, no remote URLs. Use package atomic copy, typed fill-image registration and manifest synchronization; rollback newly created files on failure, never remove pre-existing resources. Existing materializer silently prefers authored same-name declarations: new API prechecks conflicts without changing legacy behavior. DocumentStyles package access via optional provider, not global state.

Page fill projection: fo:background-color for solid/none, draw:fill and compatible draw attributes, synchronized drawing-page properties; bitmap additionally style:background-image child with same href as named fill declaration. Header/footer same local property mapping without drawing-page style. Frame uses graphic properties, not page-specific child. Bitmap repeat/stretch map to style:repeat, child repeat where required; preserve Writer-compatible defaults verified by fixture. Gradient use named draw:gradient; no arbitrary fallback color guessed from reference; establish required fallback by focused Writer tests. On explicit fill transition remove stale fill-specific attributes and background-image children, preserve unrelated properties and resources. Do not delete shared definitions. No opacity, tile offsets, custom image sizing, hatch, multi-stop authoring in this slice.

## 6. Page columns

Reuse H01 RelativeColumnWidthNormalizer and validated common column vocabulary (count, weights, gap or explicit indents, separator). No Section balancing property on page. Count 1..16383, positive integer weights, exact normalized sum 65535 when explicit, no zero-width normalized columns. Gap and explicit indents mutually exclusive for generated options; preserve authored simultaneous representations when untouched. Explicit columns group replaces column configuration atomically; count 1 resets multi-column configuration. Native separator before column children; background-image before columns, preserve footnote separator and unrelated children. Match H01 separator semantics and test native page behavior. No changes to table normalization.
