## Implemented

The additive `OdtTemplate::automateNativeObjectActions()` entry point accepts the source `TemplateContract` and a READY `ConcretePreflightResult`. `NativeObjectActionExecutor` selects only explicit native-action resolutions represented by that preflight, verifies their target evidence, localizes every selected target before mutation, checks destructive Section ownership conflicts, and dispatches in the supplied preflight order. It does not resolve application data, rerun mapping, execute E3/E5, or save/finalize.

Section replacement delegates BODY targets to the established `SectionTarget::replaceContent(OdtElement)` facade. For supported `styles.xml` master-page regions, the same `SectionMutationService` semantics operate on the D1 provenance-bounded `SectionWorkingTarget`. Bookmark replacement delegates BODY targets to `BookmarkTarget::replaceText(string)`; the same `BookmarkMutationService` range semantics have a bounded styles-region entry point. Public SECTION-03 and Bookmark facades remain content.xml-based.

Frame replacement uses TemplateContract provenance to localize one unique frame in `content.xml` BODY or the identified `styles.xml` master-page header/footer. `FrameImageReplacementService` shares only the low-level image-reference and optional-dimension update with the legacy imperative facade. E4 dimensions follow the accepted rule: no options preserves both existing dimensions; width-only or height-only derives the other dimension from the replacement image's intrinsic ratio while retaining the explicit unit; two dimensions are applied verbatim. Raster ratio comes from intrinsic pixel dimensions. SVG ratio uses a positive viewBox width/height, or positive explicit width/height with matching units; ambiguous/missing geometry is rejected for one-dimensional sizing. Zero- and two-dimensional SVG replacement does not require a ratio. No legacy 5cm × 3cm default leaks into E4.

The legacy `replaceImageByName()` defaults, explicit-dimension behavior, duplicate-name updates, protected `replaceImageInNamedDom()` dispatch, and non-image-frame dimension behavior remain unchanged. Selected Section replacement is rejected before mutation if a selected native target is source-owned beneath it. No family-wide action order or invocation-wide rollback is introduced.
